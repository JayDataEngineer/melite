# @melite/models-fit

The Fit family — analytic bone-scale fitting, the node family behind the fit-seat verb (the meld seat). Weightless by construction: FitRow and FitProp carry no checkpoint, so nothing downloads. No engine field is declared (the contract default reads comfyui) and the family is unoffered, so no served catalog row exists. The DECL carries no Recipe default row either — nothing pre-stamps a fit pick.

The seat action is the verb's backend: FitRow (the analytic fit row) then FitProp (the body union prop under the row), then a fixed 4-view proof sheet rendered at the verb's framing (768, framing 1.2, focal 50, samples 64, transparent). The flow row routes; this declaration owns the graph. Params are the two files the caller names — `body`, `prop` — plus `bone`, which is required and refuses empty: a bone names a bone in the body being fitted, the vendor's FitRow refuses an empty one, the flow declares it required at the door, and the engine judges existence against the SOMAX body. The node's other fields are pinned verbatim in FIT_ROW — the FitRow node's own declared defaults (model name, align socket, seat ratio 0.22, fit reference bones, finger and thumb bones, target width), named here once.

The 2026-09-16 retirement order killed the fit card; the family is the sanctioned seam — flows' family-action stages are the only riders.

## Declaration

`src/index.ts` declares the DECL and the `family-fit` plugin; `src/actions.ts` owns the seat segment and FIT_ROW.

## Model Experience

#### What the model sees

None — the package contributes no model-visible input. The DECL registers in the models registry only; the catalog emission serves it no row (only offered comfyui-engine families serve), and it registers no session events and writes no prompt segments.

#### Token effect

Zero-direct token effect — the package registers a model family and composes engine graphs; it writes no prompt text into any model request.

#### KV Cache effect

Independent — the package contributes no persistent prompt prefix, so registering or removing the family invalidates nothing cached.

## Known Limitations and Deferred Work

- **The fit card stays dead** — the 2026-09-16 retirement order keeps it killed; the family is reachable only through flows' family-action stages, never a bench card.
- **The bone is the caller's** — no constant can know it; an absent or empty bone refuses at the door, and a name the body does not contain earns the engine's own verdict.
- **No fresh-card landing** — the DECL declares no Recipe default row, so nothing pre-stamps fit picks for new cards.
