# character-factory

The supplied-body chain, estate-native. TWO card stages on the
`comfyui` card plane (rig → motion), agent-driven through the queue
door — the registry row (`flowsRegistryRows.ts` CHARACTER_FACTORY)
is the TEMPLATE, this leaf is the agent face.

- **The body rides the `mesh` initial** (a GLB path): an anny bake,
  a TRELLIS/img-to-mesh lift artifact, an estimator body — any bare
  human mesh, the rig lane's own feed.
- **The lift is upstream, not a stage** (2026-11-01, the rig-hop
  dead ref): the lift's served producer (img-to-mesh's
  Save3DAdvanced) is a terminal FILE_3D save no in-graph hop can
  carry, so the lift presses through the img-to-mesh card door or
  the object-forge row and its artifact path feeds this row (the
  run-chain).
- **Multi-stage drives at start** (the curated-lane lift: named
  registry flows run multi-stage through the {flow:} door; the
  start refusal is hand-authored inline only). Stages also drive
  one card at a time for surgical re-takes (`{model:}` door or the
  bench); the done-stage skip makes re-runs cheap.
- **Creature motion is never a registry stage.** The MOTION phase
  (unimate dataset clip → rig `copy` bridge) rides the game-profile
  MCPs — unimate is an MCP, not melite. The leaf skill documents the
  bridge; the registry stays melite cards only.
- **Unity is the EDITOR phase**, not a stage: the animated GLB
  imports through the game profile's Unity MCP. (The rig `fbx` arm
  died with the blender lane — GLB is the only rig output.) No
  Unity seats, servers, or proxy nodes in melite (M12/M15).
